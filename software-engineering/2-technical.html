Python

Basic


# Explain whether Python pass by value or reference

Pass by value - copy of variable value (stored in a new location in memory) is passed to function, so updates does not impact original variable
Pass by reference - memory address of variable is passed to function, so updates impacts original variable
Pass by object reference - function gets copy of variable but that copy points to same object in memory. If mutable object is passed, it will be modified, if immutable object is passed, new object will be created

# Explain Global Interpreter Lock

There will be no deadlock due to a single thread
Can slowdown CPU bound exeuctions
Using multi-core environment can be a solution

# Explain method overloading and method overriding in Python

Method overloading - same signiture but different arguments within the same class
Method overriding - same signiture and arguments between parent and child class

Class method - access and modify class variables, @classmethod
Static method - utility functions inside the class, @staticmethod

# Explain encapsulation, inheritance, polymorphism

Encapsulation - hiding information within the class via private variable and method
Inheritance - let child class to re-use non-private methods from parent class
Polymorphism - same form but different implementation (method overloading and method overriding)

class Lottery:

    def __init__(self):
        self.lotteries = defaultdict(int)

    def create(numbers, owner):
        self.lotteries[numbers] = owner

    def delete(numbers)
        del self.lotteries[numbers]

    def pick_winner():

        winning_number = []
        for _ in range(7):
            winning_number.append(random.randint(1,99))

        winning_number = tuple(winning_number)

        return self.lotteries[winning_number]

Kubernetes

General

  • Explain pros and cons of kubernetes
    • Pros - automated scaling, rolling updates
    • Cons - version maintenance, security
  • Explain difference between Helm and Operator
    • Helm is not aware of changes made manually
    • Operator is aware of changes made manually
  • Explain service mesh (Ex. Istio)
    • Controls traffic in and out of pods
    • Encrypts traffics
    • Deployed as side-car container
  • Explain cluster autoscaler
    • Scales up and down nodes based on workload
  • Explain taint and toleration
    • Taint - mark Node to reject Pod
    • Toleration - allow Pod to ingore certain taint

Namespace

  • Explain namespace
    • Virtual clusters (or segregation) within a cluster
  • Explain networking between namespaces
    • Services in different namespaces need fully FQDN to communicate

  • Explain difference between Deployment, StatefulSet, DaemonSet
    • Deployment - abstraction of Pods, manages Pod lifecycle, supports rolling updates (updates provisions new pods, direct traffics to new pods, and delete olds pods)
    • Statefulset - provide uniqueness and ordering of pods (pods are uniquely named like 0, 1, 2, etc / when pods are scaling up and down, it is done in order)
    • Daemon - provisions one pod per node
  • Explain Job
    • Pods that run as job terminates upon completion

Pod

  • Explain init container
    • Container that always runs before the application container
  • Explain Pod Disruption Budget
    • Determines minimum number of pods that must be running when pods are scaled down
  • Explain pod affinity and pod anti-affinity
    • Determines which Pods should go together or separately
  • Explain livenessProbe and readinessProbe
    • LivenessProve - checks whether container is running or not
    • readinessProve - checks wheter container is ready to respond to requests
  • Explain lables and selectors
    • Label - information that can be used to identity Pods, Services, etc
    • Selector - uses label to identity Pods, Services, etc
  • Explain NodeAffinity
    • Specifies which Pods should be assigned to which Nodes
  • Explain horizontal pod autoscaler
    • Automatically scales up or down Pods based on CPU/memory usage
  • Explain what happens when CPU/memory exceeds the limit
    • Memory - container is killed with OOM error
    • CPU - CPU is throttled, or application is slowed down

Ingress

  • Explain Ingress and Ingress Controller
    • Ingress - abstraction of services, allowing external users to connect to services, routes based on hostname and path
    • Ingress Controller - route external traffic to Services based on Ingress rules

Service

  • Explain service
    • Exposes group of Pods, needed because Pod IP can changes when they are scaled up or down
  • Explain difference between ClusterIP, NodePort, Load Balancer
    • ClusterIP - exposes internal IP of Pods, can only communicate within the cluster
    • NodePort - exposes IP and port of K8s node externally
    • Load Balancer - exposes public IP that allows traffic into K8s cluster (using vendor's load balancer)
  • Explain headless service
    • Does not assign cluster IP, rather uses DNS to expose Pods to Services
